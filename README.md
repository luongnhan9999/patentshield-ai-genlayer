# PatentShield AI (Autonomous Open-Source IP Prior Art & Patent Clearance Escrow)

PatentShield AI is a decentralized Intelligent Contract on GenLayer that automates prior-art invalidation bounties for software patents, protecting open-source builders from patent trolls.

## Project Structure
- `contracts/patent_shield.py`: The Intelligent Contract file. Contains the lifecycle logic, non-deterministic web page rendering, LLM-driven audit, and escrow payouts.
- `tests/test_patent_shield.py`: Comprehensive unit testing suite covering creation, cancellation, audit consensus (INVALIDATED/UPHELD/ABORT), and platform arbiter overrides.

## How it Works
1. **Challenge Creation**: A challenger deposits a bounty (using native currency) along with a target patent claim specification and its URL.
2. **Prior-Art Submission**: A researcher submits prior-art evidence URLs.
3. **Consensus Auditing**:
   - Each validator node independently renders the patent page and the submitted evidence pages via on-chain browser (`gl.nondet.web.render`).
   - Each node runs an LLM evaluation (`gl.nondet.exec_prompt`) to determine if the patent claim is `INVALIDATED` (lack of novelty), `UPHELD`, or `ABORT`.
   - All nondet calls are directly inside `leader_fn()`, which is passed to `gl.vm.run_nondet()`.
4. **Resolution**:
   - If `INVALIDATED`, 98% of the bounty goes to the researcher, and 2% goes to the treasury.
   - If `UPHELD`, the challenge goes back to `PENDING` so other researchers can submit better prior art.
   - If `ABORT` (due to low confidence, broken evidence, or LLM failure), the challenge escalates to the platform arbiter for manual review.

## Public API
- `create_challenge(target_patent_claim: str, patent_doc_url: str) -> str` (payable)
- `cancel_challenge(challenge_id: str) -> None`
- `submit_prior_art_and_audit(challenge_id: str, researcher_payout_addr: str, prior_art_url_1: str, prior_art_url_2: str) -> None`
- `resolve_escalated_challenge(challenge_id: str, action: str, researcher_payout_addr: str) -> None`
- `get_challenge(challenge_id: str) -> str` (view)
- `get_challenge_counter() -> int` (view)
- `get_treasury() -> str` (view)

## How Consensus & The Validator Works

Unlike traditional smart contracts, GenLayer contracts achieve consensus on subjective decisions. The custom `validator_fn` in this contract compares the **meaning** of the verdict, not the format of the output:

1. **Each validator node runs `leader_fn()` independently.** All `gl.nondet.web.render` and `gl.nondet.exec_prompt` calls are directly inside `leader_fn()` -- the function passed to `gl.vm.run_nondet()`. This satisfies the GenVM static linter requirement that every nondet call be syntactically reachable from a supported consensus block.

2. **Agreement on Meaning, Not Format.** The `validator_fn` compares the core `verdict` string (INVALIDATED vs UPHELD vs ABORT) and checks that confidence levels are in the same bucket (both above or both below the 65% threshold). It ignores natural language differences in the `reason` string generated by different validator LLMs. This ensures consensus succeeds even when different validators write different explanations, as long as they agree on the legally binding verdict.

3. **Two validators that reach different verdicts will NEVER both pass.** This is the critical design constraint from GenLayer's scoring rubric (Axis 2).

## Edge Cases Handled
- Bounty must be > 0 (`UserError`)
- Patent claim must be >= 15 characters (`UserError`)
- URLs must start with `http://` or `https://` (`UserError`)
- Web fetch failure -> `ABORT` verdict
- Low confidence (< 65%) -> auto-escalate to `ABORT`
- Only the original challenger can cancel a `PENDING` challenge
- Only the platform arbiter can resolve `ESCALATED` challenges
- Double-process prevention via explicit status lifecycle (`PENDING -> AUDITING -> SETTLED/REFUNDED/ESCALATED`)
